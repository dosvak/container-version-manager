# Container Version Manager (CVMGR) - process applications, toolkits and snapshots without wsadmin

On CP4BA there is no wsadmin; on traditional BAW the Process Admin console covers only part of the snapshot lifecycle. The Container
Version Manager puts the Operations REST API (`/ops/std/bpm/containers/...`) behind a dashboard: containers, snapshots, environment
variables, cleanup and the queue of asynchronous operations. Generated by `tools/build_cvmgr.py` on `tools/utilapp.py` (vanilla BAW:
OOB UI Toolkit, client-side human service, business objects, Ajax service flows, no scripts in views).

## Function

| Tab | Content | Actions (Operations REST) |
|---|---|---|
| Containers | process apps and toolkits (kind filter, text filter on acronym / name / description): acronym, name, kind, archived, tracks, created, creator, description; orphaned toolkit snapshots | Lookup (`GET /std/bpm/containers?type=&optional_parts=branches`), Snapshots of container, Archive / Restore (`POST .../{acr}/archive|restore`), Delete (`DELETE .../{acr}`, confirmation), Orphaned toolkit snapshots (`GET .../orphaned?optional_parts=version_details`), Export CSV |
| Snapshots | snapshots of a container (named snapshots of every track + track tips): acronym, name, track, tip, active, default, status, archived, capability, created, creator, description | Activate, Deactivate (force), Deactivate + suspend instances (`suspend_bpd_instances=true`), Make default, Archive, Restore, Stop (`POST .../versions/{v}/<action>`), Details (`GET versions/{v}` + `env_vars` + `epvs` + `team_bindings`), Variables (opens the tab), Delete snapshots (`DELETE .../versions?versions=&force=true`, queued), Export CSV; **unnamed snapshot cleanup** (`DELETE .../versions?kept_number=&created_before=&delete_archived=&branch_name=`, Workflow Center, queued) |
| Environment variables | variables of a snapshot with their current values, EPV variables with their current values | Lookup (`GET .../versions/{v}/env_vars`, `/epvs`), row selection -> editor, Set value (`POST .../env_vars {pairs: [{name, value}]}`), Export CSV |
| Cleanup | container, snapshots, instance states, ended before, force, transaction slice; task status / type, process name, maximum duration | Count instances (`GET /std/bpm/processes/count`), Delete instances (`DELETE /std/bpm/processes`, queued), Delete closed tasks (`DELETE /std/bpm/tasks`, BAW 24 / CP4BA only - the 8.6.2 lab has no such resource), Resume suspended instances (`POST /std/bpm/processes/resume?container=&version=`, queued) |
| Queue | URL of the last accepted request, status, result | Refresh status (`GET /system/queue/{id}?key=`; states pending / running / success / failure) |

Every queued action switches to the Queue tab with the URL of the accepted request. The Process Center refuses the Workflow Server
operations (make default, stop) with a clear message; the tool shows the server's answer.

## Notes on the API (verified on the 8.6.2 lab, Process Center)

* `GET /std/bpm/containers/{acr}/versions` lists only the **named** snapshots; the unnamed tip of a track comes with
  `optional_parts=branches` (`branches[].tip`, acronym = the snapshot uuid). Instance counts and the v2 `versions=` filter accept that uuid.
* Timestamps of `/ops` are local server time with a lowercase `z` (`2026-09-19T15:48:23z`); the classic API answers UTC.
* `GET .../install_messages` needs the `server` parameter on a Process Center (`CWTBG0663E`).
* The environment variable value set through `POST .../env_vars` is stored for the snapshot (the next `GET env_vars` shows it), but the
  engine reads environment values when it loads the snapshot: on the 8.6.2 Process Center a running snapshot kept its cached `tw.env`
  (verified with Instance Purge: a changed `smtpPort` / `approverEmails` stayed at the old value, also after deactivate + activate) - the
  change takes effect when the snapshot is reinstalled / the server restarts; a re-import restores the package value.
